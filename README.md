# WE School Backend

FastAPI backend for **WE School** (WE Applied Technology Schools), a school management and communication platform that connects students, teachers, and School Admins. It provides authentication, user profile management, school course materials, announcements, assignments, real-time chat, support contact, and AI-assisted quiz generation from uploaded course files.

## Features

- JWT-based login, password change, OTP verification, and password reset.
- User profile endpoints for the authenticated user.
- Course material lookup for students and teachers.
- Content management for announcements, files, and assignments.
- Real-time chat with WebSocket presence, delivery/seen status, pinned conversations, voice uploads, and file uploads.
- Announcement WebSocket notifications.
- Quiz generation and evaluation for supported course materials: PDF, PPTX, and DOCX.
- Static file serving from `/uploads`.

## Tech Stack

- Python 3.12+
- FastAPI and Uvicorn
- SQLAlchemy
- Alembic migrations
- Pydantic settings and schemas
- PostgreSQL (Neon serverless Postgres in production)
- SMTP for support and account email flows
- Google Gemini API for quiz generation

## Getting Started

Clone the repository and create a virtual environment:

```bash
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

Create a `.env` file in the project root:

```env
APP_NAME="WE School"
APP_VERSION="2.0.0"
DEBUG=false
# Pooled connection (PgBouncer) for application traffic.
DATABASE_URL="postgresql://user:password@host/neondb?sslmode=require"
# Direct (unpooled) connection used by Alembic migrations; PgBouncer does not
# support the session/DDL locks that migrations need. Must NOT contain "pooler".
DATABASE_URL_UNPOOLED="postgresql://user:password@host/neondb?sslmode=require"
SECRET_KEY="replace-with-a-long-random-secret"
ALGORITHM="HS256"
ACCESS_TOKEN_EXPIRE_MINUTES=1440
RESET_TOKEN_EXPIRE_MINUTES=5
SMTP_HOST="smtp.example.com"
SMTP_PORT=587
SMTP_USERNAME="your-smtp-username"
SMTP_PASSWORD="your-smtp-password"
FROM_EMAIL="noreply@example.com"
GEMINI_API_KEY=""
# Optional: set true ONLY for throwaway/local databases.
# Alembic is the source of truth for the schema; leave it false in production.
AUTO_CREATE_TABLES=false
```

Make sure PostgreSQL is running and the database in `DATABASE_URL_UNPOOLED` exists.

### Neon setup

The production database is a Neon project. Two connections are used:

| Variable | Purpose |
| --- | --- |
| `DATABASE_URL` | Pooled endpoint (PgBouncer) for runtime application traffic. |
| `DATABASE_URL_UNPOOLED` | Direct endpoint for Alembic and other DDL. |

Notes:

- URLs pointing at `*.neon.tech` without an `sslmode` parameter automatically get `sslmode=require` appended (`app/db/database.py`).
- Retrieve both values with the Neon CLI (`neon env pull`) or from the Neon console connection details. Never commit real credentials.
- Migrations must run against `DATABASE_URL_UNPOOLED`; a `pooler` host will fail during DDL.

## Database Migrations

Alembic is the single source of truth for the schema. The chain starts at the
baseline revision `000000000001` (`alembic/versions/000000000001_baseline_schema.py`),
which creates the legacy base schema (17 tables) that the remaining 34 revisions
build upon, ending at head `d25ea49a9110`.

**Fresh / empty database:**

```bash
alembic upgrade head
```

**Existing database that already has the full schema** (for example a database
previously created with `create_all()`), do not run `upgrade` — the baseline
refuses to run against a populated database. Stamp the current head instead:

```bash
alembic stamp d25ea49a9110
```

The baseline guard prints exactly this instruction if it detects existing tables.

Startup order: run migrations (or the stamp) **before** starting Uvicorn.
`alembic upgrade head` is safe to re-run; it is a no-op once at head.

Adding a change:

```bash
alembic revision --autogenerate -m "describe_change"
alembic upgrade head
```

Review autogenerated output before committing — autogenerate does not detect
every change (for example stored procedures or enum values).

## Run the API

```bash
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

Open the interactive API docs at:

```text
http://localhost:8000/docs
```

## API Areas

- `GET /` and `GET /health`: service status.
- `/auth`: login, logout, forgot password, OTP verification, reset password.
- `/users`: authenticated profile and password updates.
- `/materials`: student and teacher material listings.
- `/announcements`: announcements, recipients, unread counts, and notification WebSocket.
- `/files`: material file upload and management.
- `/assignments`: assignment listing and management.
- `/chat`: chat history, search, uploads, message edits/deletes, presence, and chat WebSocket.
- `/contact`: authenticated support/contact form.
- `/quiz`: quiz generation and answer evaluation.

## Tests

```bash
python -m unittest test_neon_integration -v
```

`test_neon_integration.py` covers app health, the `/api/neon/*` endpoints, and
Alembic configuration; it is offline for Postgres (endpoint checks do not require
a live database) but the app logs a non-fatal warning if `DATABASE_URL` is
unreachable. Offline migration-chain checks live in `tests/`:

```bash
python -m unittest discover -s tests -v
```

## Development Notes

- Keep route handlers thin; put business workflows in `app/services`.
- Add database changes as Alembic revisions under `alembic/versions`.
- Do not commit `.env`, virtual environments, `__pycache__`, `*.pyc`, or uploaded files.
- The app creates upload directories on startup: `uploads/materials`, `uploads/content`, `uploads/voice`, and `uploads/files`.
